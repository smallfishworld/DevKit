# Proposal: fix-split-panes

## 为什么

合并分屏（v0.3.1）交付后用户反馈两处问题，排查中又确认了一处更严重的缺陷：

1. **分隔条不显示、拖不动**：分屏网格里的分隔条只指定了所在列，在 DOM 中却排在第 3 列的面板之后。按网格自动放置规则，光标的列位置回退会换行，分隔条实际掉到第二行——只剩窗口底边一条几像素高的小条，两面板交界处是空的，面板底部也因此多出一条空白。
2. **默认不是均分**：用户本机留有 29.7% 的记忆宽度，每次分屏都从它恢复，而分隔条又看不见、无法调回。
3. **合并与拆分会断开连接**：合并改变了组件树（面板从独立标签挪进分屏容器），面板被销毁重建；串口、SSH、本地终端面板在卸载时都会释放会话，于是已连接的会话在合并、拆分的瞬间被断开，终端已有输出被清空——与现行 spec「面板状态与连接保持」相悖。

## 变更内容

- 内容区改为「面板常驻的网格」：每个面板始终是内容区的直接子项，合并/拆分只改变落位（显隐、所在列），组件实例不重建，连接与终端输出原样保留。
- 分隔条显式落位在两成员之间并贯通全高，增加常驻可见的中央把手；两成员按扣除分隔条后的宽度分配比例，默认严格均分。
- 宽度记忆值加校验：缺失、非数值或越界都按未记忆处理，回到均分；丢弃分隔条错位版本写出的旧值。
- 拖拽被取消或指针捕获丢失时结束拖拽，之后的悬停不再改变宽度。
- 单例工具并入分屏后仍只此一份；并入其他分屏中的会话时先移出原分屏，同一面板不会挂在两个分屏下。
- 分屏内超出高度的面板可滚动（原实现被裁切且无法滚动）。
- 功能名从「合并分屏」统一为「分屏」（右键菜单等界面文案）。
- 分屏标签右键菜单新增「关闭左侧分屏 / 关闭右侧分屏」：只释放被关一侧，另一侧原地还原为独立标签并保持连接。
- 两个终端成员的分屏共用一条快捷命令栏：自带的命令栏不再显示，分屏左侧只留一条共享栏，栏顶标出发送目标；点进（或键盘聚焦）哪个终端命令就发给哪个，该终端顶部亮主色标识线；共享栏可拖宽、可折叠，宽度与折叠状态记忆。混合分屏（含非终端成员）不共用，各用各的。

## 影响

- 渲染层：`App.vue`、`styles/global.css`、`components/split-tab.ts`、`components/SplitQuickCmds.vue`（新增）、`components/TabBar.vue`、`composables/useTermMacroTargets.ts`（新增）、`stores/tabs.ts`、三个终端面板（`SerialPanel.vue` / `SshPanel.vue` / `LocalTerminalPanel.vue`）。
- 主进程、preload 与 IPC 协议零改动。
- 现行行为变化落在 workbench 的两条要求：分屏标签并排工作、分屏宽度调整与持久化。
- 宽度的记忆与恢复方式不变：仍是全局一个宽度，重启后首次分屏时恢复。
