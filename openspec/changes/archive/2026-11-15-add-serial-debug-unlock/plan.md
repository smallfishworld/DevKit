# 串口快捷命令 Debug 解锁实施计划

1. 增加串口快捷命令的「解锁 Debug」步骤。步骤保存设备配置名称，复用现有编辑、回放和导入导出。等待设备确认成功后再回放后续步骤。
2. 在主进程实现按连接执行的解锁任务。先确认内网服务可用及登录态，再获取串口写入权、发送 `debug`、读取本次设备挑战、请求口令、发送一次口令并验证设备结果。分别处理超时、取消和断开。
3. 使用独立、受沙箱保护的 Electron 会话展示 OA 登录。公司配置指定 HTTPS 解锁网站、允许的认证跳转来源、会话检查和取码接口。Web 页面使用正常登录流程，取码只通过该会话访问配置的业务接口。配置及接口示例使用虚构主机，真实地址由公司部署方在用户数据目录提供。
4. 验证主进程只向本次连接发送口令、拒绝未授权的接口结果，并保护发送审计及设备回显中的口令。恢复后续终端交互，避免把会话凭据、口令或接口地址放进可导出的宏。
5. 使用本地模拟 OA、Cookie 接口和模拟串口验证。覆盖首次登录、会话复用、取码拒绝、拆包、回显、断线和取消。运行类型检查、完整单测、构建和 Electron 界面冒烟，再将代码和规格上传到 GitHub 功能分支。

范围为公司批准的 Cookie 会话接口及串口设备。真实 OA、接口字段和设备输出仍需在公司环境验收。
