# 设备插件设计
## 基线与数据流

串口接收先保留原始字节与主机接收序号/时间，文本展示继续流式解码和批处理。插件监听不依赖 Vue 页面渲染。文件传输和敏感事务具备明确的独占边界，防止协议数据误触发其他自动应答。

## 职责
- Serial host：原生串口、连接代际、RX 订阅、统一 TX 仲裁、事务租约、传输互斥、日志和脱敏。
- Plugin service：插件清单、安装存储、配置校验、实例、会话绑定、动作发现、进程监管。
- Plugin worker：加载预编译 JS，维护插件私有状态和流缓冲，通过带实例/连接身份的 RPC 使用串口。
- UI：通用列表、配置表单、实例绑定、动作执行、自动监听和错误状态。
- Built-in OA plugin：现有登录、取码、挑战识别和结果业务规则。兼容入口保留，业务逻辑不复制。
- Simple responder：无 OA 的文本/HEX 插件，检验新行为是否只需独立插件包。

## 身份与版本
插件包 id/version/apiVersion 与用户配置实例 id/configVersion 分开。动作引用使用 pluginId/instanceId/actionId，旧 profile 保留兼容映射。每次连接创建新的 connectionId，任何异步写入必须核验当前会话身份。插件缺失时保留配置和宏，给出可操作的错误。

## 事务与资源
所有发送源共享串口控制权；完整请求-响应流程持有事务，不能只排队单次 write。租约取消、断开、休眠、进程退出均释放；超时和异常不得留下锁。数据订阅、定时器和等待器必须在 dispose 回收。停止监听与停止在途任务的语义分别明确，禁用插件要取消全部在途任务。

## 配置与热更新
配置首先在主进程校验，再原子保存；进行中任务持有启动时快照。配置改变不复制旧任务 busy 状态到新监听对象。会话自动布防不随安装或配置导入默默开启。
Schema 子集和不支持字段必须有文档，默认值与校验共用纯函数；复杂对象可 JSON 编辑。API/configVersion 当前均为 1；旧 OA 文件导入为独立实例，尚不提供第三方自定义配置迁移钩子。

## 独立进程
外部插件在 utilityProcess 中执行；进程仅通过宿主代理使用目标串口。进程启动握手、命令执行、请求超时、失联和退出需可诊断并回收租约。utilityProcess 可用完整 Node API，因此只支持用户信任的插件，清单能力不是安全沙箱承诺。
程序打包时必须包含 worker 入口，测试不能仅覆盖源码目录可运行。

## 认证与秘密
现有 OA 登录窗口/专用 Cookie 会话继续由主进程管理；口令不能进入普通日志、宏存储、错误诊断。原始敏感数据不能广播给无关插件。保留跨 RX 批次回显脱敏。

## 安装与更新
校验 manifest、API 版本、入口路径、重复 ID、包大小和文件范围。先复制到临时目录并校验，成功才切换；失败保留原版本。更新运行中插件先停实例并清理，在下一次明确启用后使用新版本。不在安装过程中自动运行插件代码。

## 验证
主机纯函数/模拟串口/子进程测试和真实 Electron 冒烟互补。Box 为 Linux，Windows 原生模块和打包由已有 Windows CI 验证；在结果里明确区分模拟串口、UI、真实硬件和 Windows 验证。
