## Context

DevKit 的可见文案分布在 Vue 工作台和各工具面板、共享工具元数据、主进程服务与 Electron 原生窗口中。语言切换必须实时更新界面，但串口、终端、网络、传输和插件会话由稳定的 `panelId` 与主进程服务承载，不能通过刷新页面或重建面板来实现。GitHub Release 发布流水线还会回写下载信息，而已部署更新读取器依赖精确的 `## 下载` 标题。

规范依据为 [workbench delta](specs/workbench/spec.md)。

## Goals / Non-Goals

### Goals

- 支持 `zh-CN` 与 `en` 两种应用语言，默认中文，记住用户选择。
- 让全部 DevKit 自有界面文案使用统一、可检查的本地化来源，并覆盖渲染进程与主进程原生文案。
- 语言切换只更新展示层，不改变标签、连接、任务、缓存或用户数据。
- 提供完整英文 README，并让一次 Release 同时服务中英文用户且兼容旧更新读取器。

### Non-Goals

- 不翻译终端输出、串口收发内容、网络报文、文件内容、日志载荷、用户输入或设备返回值。
- 不翻译第三方网页、插件自带内容、外部程序输出和操作系统提供的通用控件文案。
- 本次不增加跟随系统、更多语言、在线翻译或按工具独立选择语言。

## Decisions

### 1. 单一应用语言与稳定持久化键

设置只接受 `zh-CN` 和 `en`。缺少、无效或旧版本尚未写入该设置时使用 `zh-CN`，确保升级用户的现有中文体验不变。语言使用稳定的本地设置键持久化，并在工作台首次绘制前加载，避免先显示错误语言再闪烁切换。

选择新语言后，渲染层通过响应式 locale 重新求值当前界面文案；主进程同步收到已验证的 locale，用于之后创建或更新的 DevKit 原生窗口、对话框、菜单、通知和错误提示。切换过程不得刷新 renderer、重建工具面板或重启主进程。

### 2. 共享消息目录覆盖 DevKit 自有文案

建立带类型约束的消息键与 `zh-CN` / `en` 目录。工具名称、说明、按钮、字段、状态、空态、确认与错误提示等应用自有文案从目录解析；带变量的消息使用命名参数，避免拼接导致语序无法翻译。主进程使用同一语言标识和等价消息资源，跨 IPC 只传稳定状态/错误标识和参数，展示层决定面向用户的文案。

测试应校验两种目录键集合一致、无空白译文，并对动态插值和主要纯逻辑入口做回归。开发阶段的缺失键应明显暴露；生产环境可安全回退中文，不能因单个缺失键阻断工具操作。

“DevKit 自有文案”包括应用壳、设置、全部内置工具、应用创建的辅助/认证/更新窗口、应用定义的原生菜单、对话框、通知及错误说明。协议内容、终端/设备/远端返回、用户文件与输入必须作为不透明数据透传；插件或外部页面自带文案不纳入目录，也不得被自动改写。

### 3. 语言切换与会话生命周期解耦

locale 是工作台级展示状态，不进入工具连接身份，也不作为面板组件的重建 key。已打开的面板就地重新渲染文案，连接对象、运行中的传输、终端缓冲、表单值、标签顺序和 `panelId` 保持不变。对于不能原地改写的瞬时系统对话框，切换后新打开的对话框必须使用新语言，切换不得为了替换其文案而中止业务会话。

### 4. README 与 Release 的双语契约

`README.md` 保持中文主文档，新增内容完整对应的 `README.en.md`；两者顶部提供明确的互相跳转链接。两份文档各自可独立完成安装、使用、开发与发布信息的阅读，不用在段落间来回切换。

每个 Release 的说明包含中文章节和 English 章节，二者之后共用一张双语下载表。下载段标题必须逐字保持 `## 下载`，不得改名、翻译或生成第二个同级下载段，以兼容已发布应用的解析方式。表头与说明同时包含中英文，但附件名继续使用稳定的 `DevKit-portable.exe` 与 `DevKit-win-x64.zip`。

发布工作流只允许替换一对显式 marker 之间的下载表内容。marker 外的中文、English、迁移提示和人工说明原样保留；marker 缺失、重复或顺序错误时流水线应失败而不是重写整篇 Release。应用内发布说明区域展示 Release 中的中文和 English 章节，不因当前应用语言隐藏另一章节。

## Failure Handling

- 持久化 locale 无效或读取失败时回退 `zh-CN`，工作台继续启动。
- 主进程同步语言失败时报告可诊断错误，但不得断开现有会话；渲染层仍可保持已选择的语言，后续允许重试同步。
- 单个消息键缺失时回退中文并留下可诊断信息，不能把内部 key 作为正常用户文案静默发布。
- Release 下载表 marker 不满足唯一配对条件时 CI 明确失败，避免破坏双语发布说明。

## Trade-offs

- 初期只支持两种明确 locale，比自动跟随系统更可预测，但用户需要手工选择英文。
- 应用内始终展示两种 Release 章节会增加说明长度，但能保证同一发布内容完整可见，也避免解析或回写时丢失另一语言。
- 中文回退提高运行可靠性；目录一致性测试和 UI 冒烟用于防止回退掩盖未完成的英文覆盖。
