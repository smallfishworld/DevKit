# Workbench

## Purpose

DevKit 的跨平台本地多工具工作台，统一管理工具面板、按需懒加载、平台能力裁剪、状态和持久化配置。它覆盖离线启动、会话隔离、用户设置恢复和本地数据保护，是其他工具共享的基础交互契约。

## Requirements

### Requirement: 跨平台离线工作台与平台能力解耦

应用 MUST 支持在 Windows、macOS 与 Linux 本地离线运行核心通信与调试工具（串口、SSH、本地终端、网络调试、TFTP、桥接、数据转换与文本对比、设备插件），无需云端账户或外网服务。依赖 Windows 原生 API 的工具（键鼠输入测试、键鼠宏、取色器）MUST 按 `process.platform === 'win32'` 在主进程与渲染进程工具注册表条件加载，并将 `koffi` 与 `uiohook-napi` 声明为 `optionalDependencies`。

#### Scenario: 非 Windows 平台启动

- **WHEN** 用户在 macOS 或 Linux 上启动 DevKit
- **THEN** 主进程跳过 Windows 专属原生服务加载，工具箱仅展示当前平台支持的核心工具，且不因缺失 Windows API 报错。

#### Scenario: 离线启动

- **WHEN** 设备没有互联网连接，用户启动 DevKit
- **THEN** 工作台及本地工具仍可打开和使用。

### Requirement: 多面板会话与按需懒加载

工作台 MUST 支持以标签承载独立工具面板，按工具声明允许多开或复用单例；渲染进程工具注册表 MUST 使用 `defineAsyncComponent` 对各工具面板按需拆包懒加载，避免首屏全量加载所有面板代码。合并分屏标签的各成员面板 MUST 同样遵循懒加载与按 panelId 的会话隔离。

#### Scenario: 并行调试

- **WHEN** 用户分别打开两个串口工具面板并切换标签
- **THEN** 两个面板的连接配置和状态彼此隔离，切换不会主动销毁会话。

#### Scenario: 合并分屏下双会话隔离

- **WHEN** 用户把 COM3 与 COM4 串口合并为一个分屏标签
- **THEN** 两成员的数据流、日志与连接状态按 panelId 完全隔离，互不串扰。

#### Scenario: 生产构建拆包

- **WHEN** 执行 `electron-vite build`
- **THEN** 各工具面板被拆分为独立的异步 JS/CSS chunk，仅在用户首次打开对应工具时加载。

### Requirement: 合并分屏标签并排工作

工作台 MUST 支持「合并分屏」：把任意两个非 home 标签合并为一个分屏标签——标签条上仅显示一个条目（标题合并为 "A | B"，仅一个关闭按钮），内容区左右并排同时渲染两个成员面板（非 CSS 隐藏）。分屏标签 MUST 可整体拖拽排序；MUST 支持拆分回两个独立标签（面板与连接状态保留）。工作台 MUST 仅支持两面板合并，不提供三面板以上或上下分屏。

#### Scenario: 两个串口合并并排

- **WHEN** 用户在 COM1 标签上右键选择「合并分屏」并在选择器中选中已打开的 COM2 标签
- **THEN** 标签条上 COM1 与 COM2 合并为一个条目（标题 "COM1 | COM2"、单个 X），内容区左右并排显示两个面板，各自的连接与数据流互不影响。

#### Scenario: 合并时新开工具

- **WHEN** 用户在某标签上发起「合并分屏」并在选择器中选择一个未打开的工具
- **THEN** 该工具的新实例作为第二个成员并入分屏标签并并排显示。

#### Scenario: 关闭分屏标签

- **WHEN** 用户点击分屏标签的 X 或中键关闭
- **THEN** 两个成员面板一并关闭并释放资源，会话按身份记入最近会话。

#### Scenario: 拆分回独立标签

- **WHEN** 用户在分屏标签上右键选择「拆分为独立标签」（或按 `Ctrl+Shift+\`）
- **THEN** 成员还原为两个独立标签，面板状态与连接保持，焦点落在第一个成员。

#### Scenario: home 保护

- **WHEN** 用户尝试合并「工具箱」home 标签
- **THEN** 操作被拒绝，home 恒保持在首位。

### Requirement: 分屏宽度调整与持久化

分屏标签 MUST 提供分隔条拖拽调整两成员宽度（左成员 20%–80%），且宽度 MUST 持久化并在重启后首次合并分屏时恢复。合并分屏 MUST 提供键盘操作（`Ctrl+\` 对当前标签发起合并、`Ctrl+Shift+\` 拆分当前分屏标签）。

#### Scenario: 拖拽调宽后重启

- **WHEN** 用户拖动分隔条将左成员调至约 60% 宽并重启应用
- **THEN** 下次合并分屏时恢复上次的分隔宽度。

#### Scenario: 快捷键发起与拆分

- **WHEN** 用户在普通标签上按 `Ctrl+\` 后在选择器选中目标
- **THEN** 两标签合并为一个分屏标签；再按 `Ctrl+Shift+\` 拆分回独立标签且顺序保持。

### Requirement: 配置持久化

工作台 MUST 将用户设置和会话信息存于本机，并在重新启动后恢复适用设置。

#### Scenario: 重新启动

- **WHEN** 用户修改终端字体或会话选项并重新启动
- **THEN** 原有设置从本地配置加载。

### Requirement: 安全边界

工具的网络访问和系统权限 MUST 仅由对应功能请求，应用 MUST 不自动上传宏、设备日志或用户配置。

#### Scenario: 记录敏感操作

- **WHEN** 用户录制本地输入宏或串口日志
- **THEN** 本地数据不会被自动发送至外部服务。

### Requirement: 多平台分发构建

发布构建 MUST 为 Windows（便携版/ZIP）、macOS（DMG/ZIP）与 Linux（AppImage/tar.gz）提供对应 `electron-builder` 构建配置。

#### Scenario: 首次运行

- **WHEN** 用户启动便携版或打包产物
- **THEN** 工具可不依赖云端环境本地运行。

### Requirement: 工作台导航与内置模块目录

工作台 MUST 将工具标签和全局扩展、换肤入口布置于标题栏，工具箱 MUST 按工具用途分组并支持名称和描述筛选。

#### Scenario: 找到并打开工具

- **WHEN** 用户在工具箱搜索一个已支持的工具
- **THEN** 匹配项可通过点击或键盘激活，工作台使用该工具既有的标签实例策略。

#### Scenario: 宽屏工具箱布局

- **WHEN** 用户在宽屏（≥1440px）打开工具箱
- **THEN** 分类按竖向顺序逐组堆叠，全部分类共用同一个栅格：同类、跨类工具卡片等宽等高（描述固定占两行高度），分类标题横跨整行作为分隔，两侧不出现大片空白。

#### Scenario: 工具分类的粒度

- **WHEN** 用户浏览工具箱
- **THEN** 工具按「串口与设备调试 / 终端与网络 / 数据转换与计算 / 文本、屏幕与自动化」四类归组，每组 3–4 个工具，不出现某类塞十余个、另一类只有两三个的失衡分组。

#### Scenario: 窄窗口工具箱布局

- **WHEN** 窗口窄于 560px 时打开工具箱
- **THEN** 工具卡片改为单列排列，描述文本被截断为最多两行，卡片不横向溢出。

### Requirement: 工作台与终端工作区的版面间距

标题栏及其下方的终端工作区各栏 MUST 保持统一、可读的间距：标签不贴窗口边缘，栏内按钮不相互挤压，串口终端与 SSH 终端 MUST 使用同一套间距。

#### Scenario: 打开终端工作区

- **WHEN** 用户在 100% 缩放的窗口中打开串口终端或 SSH 终端
- **THEN** 标题栏高度不小于 44px，连接栏、操作栏、发送栏的垂直内边距不小于 7px、左右内边距不小于 12px，相邻控件间距不小于 6px；标签栏、侧栏、操作栏与状态栏的视觉密度一致。

#### Scenario: 串口与 SSH 的栏位一致

- **WHEN** 用户在串口终端与 SSH 终端之间切换
- **THEN** 连接栏、侧栏、操作栏与终端内边距一致，不出现一侧明显更紧或更松的跳变。

#### Scenario: 浏览内置模块

- **WHEN** 用户从标题栏打开扩展中心并选择一个可用内置模块
- **THEN** 详情提供打开工具标签的入口，重复打开扩展中心不会创建重复标签。

#### Scenario: 快速打开工具

- **WHEN** 用户点击标签栏的加号或按 Ctrl+K
- **THEN** 当前标签仍在背景，工具搜索面板支持方向键选择、Enter 打开及 Esc 关闭。

#### Scenario: 关闭串口标签后继续调试

- **WHEN** 用户关闭有连接参数的串口标签，然后从工具箱的最近会话重新打开
- **THEN** 新标签保留该串口的连接参数，用户主动点击连接后才打开串口。

#### Scenario: 标题栏换肤

- **WHEN** 用户打开外观浮层
- **THEN** 全部内置配色以色板栅格一次性列出（无需展开「更多」），可选择配色、按名称筛选或开关「跟随系统」；选择后界面与终端即时更新，浮层关闭后工作区继续可用。

### Requirement: 统一应用标识

工作台 MUST 使用用户最终附件中的 DK Monogram 作为统一应用标识：左侧 D 与右侧 K 连为一体，D 内部保留清晰的 D 形负空间，字母图形由蓝色向紫色渐变。标题栏 MUST 使用无底板的 DK 标识；应用图标 MUST 将同一字母图形置于深紫色圆角方形底板上。各尺寸资源 MUST 从同一可编辑 SVG 母版派生。

#### Scenario: 深浅主题标题栏与版本入口

- **WHEN** 用户在深色或浅色主题下打开工作台，并点击标题栏的 DevKit 标识入口
- **THEN** 标题栏清晰显示蓝紫渐变 DK 连体标识与 DevKit 名称，D 形负空间保持可辨认，原版本信息浮层仍可打开并展示应用及运行时版本，标题栏的导航和窗口控制保持可用。

#### Scenario: Windows 打包与运行时图标一致

- **WHEN** 用户查看本次 Windows 打包的 DevKit 可执行文件并启动应用
- **THEN** 可执行文件图标与运行时任务栏图标均使用深紫圆角底板上的蓝紫 DK 连体设计；Windows 原生窗口使用随包提供的多尺寸 ICO，其他平台沿用对应 PNG，Windows 应用身份保持为 `com.embedded.devkit`，任务栏重启入口指向 DevKit 自身。打包验证须核验目录版、便携启动器与 ZIP 内应用的图标资源，以及 ASAR 内运行时 PNG/ICO 与本次生成资源一致；Windows 原生窗口的图标和应用身份须单独验证。

#### Scenario: 插件登录窗口的应用标识

- **WHEN** 插件需要用户通过普通登录子窗口完成认证
- **THEN** 子窗口在显示前使用与主窗口相同的原生应用图标和 Windows 应用身份，登录页面地址不成为任务栏重启入口；原有认证页面、安全边界和取消行为保持不变。

#### Scenario: 辅助窗口与功能图标

- **WHEN** 用户打开宏状态条、全屏取色器或浏览工具列表
- **THEN** 辅助窗口保留既有的跳过任务栏行为，各工具保留表达其功能的图标，不因应用品牌统一而新增托盘或任务栏入口。

#### Scenario: 已发布包与已有固定项

- **WHEN** 品牌修复合入主分支，但用户仍使用旧下载包或已有任务栏固定项
- **THEN** 应用不宣称旧 Release 附件已随合并更新，也不静默改写用户已有的固定快捷方式；排查说明先核对实际构建、启动路径和固定目标，再检查 Shell 图标缓存。

#### Scenario: 单源派生小尺寸资源

- **WHEN** 维护者从确认后的 DK SVG 母版重新生成应用图标资源
- **THEN** 界面标识、单色备用标识、应用 PNG 和多尺寸 Windows ICO 保持相同的 DK 连体轮廓与 D 形负空间；ICO 包含 16、20、24、32 像素等小尺寸档位，缩小时仍能辨认字母组合，生成结果可检查是否与母版一致。

### Requirement: GitHub 应用版本更新

Windows x64 发布版 MUST 支持从官方 GitHub Release 检查同一分发格式的稳定更新、查看发布说明、按需下载和重启更新。更新过程 MUST 保留应用用户数据。

#### Scenario: 自动发现新版本

- **WHEN** 后台检查发现比当前版本新的稳定 Release，且对应的 Windows 发布包已上传并可验证
- **THEN** 工作台提示有新版本，可查看当前版本、新版本和发布说明，并可选择下载或稍后处理。

#### Scenario: 离线或发布包尚未上传

- **WHEN** 应用离线、GitHub 请求失败或发布包尚未上传完成
- **THEN** 工作台仍可操作。手工检查显示相应结果，后续仍可再次检查。

#### Scenario: 下载和延后重启

- **WHEN** 用户点击下载且完整性校验通过
- **THEN** 应用显示进度和下载完成状态，提供「重启并更新」与「稍后」。关闭并重新打开工作台后仍可使用已验证的待更新包。

#### Scenario: 重启应用更新

- **WHEN** 用户选择重启并更新且原路径满足更新条件
- **THEN** 应用正常结束现有会话，再以同一启动路径打开新版本，保留用户配置、插件和日志。

#### Scenario: 安装条件不足

- **WHEN** 应用所在目录无法安全替换或没有写权限
- **THEN** 显示原因并允许另存校验成功的更新包，保留当前程序和用户文件。

#### Scenario: 损坏的更新包

- **WHEN** 下载数据与发布附件公布的长度或 SHA-256 不一致
- **THEN** 应用报告失败并允许重新下载，原程序可以继续使用。
