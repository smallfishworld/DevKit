# DevKit 串口后台缓存与实时追赶优化实施计划

## 产品目标

默认零新增设置，串口连接期间持续后台采集并记录日志；切换标签、最小化或锁屏后，重新打开终端时可连贯看到近期输出并继续实时交互。实际系统睡眠期间硬件丢失的内容无法通过应用补回。

目标是超过 MobaXterm 的**可追溯记录能力**，但不以无条件增大 xterm 滚动缓冲导致界面卡顿为代价。必须区分「后台内存热缓存」「xterm 可视回滚」「完整磁盘历史」。

## 本次实施（P0）

| 项目 | 旧实现 | 本次设计 |
| --- | --- | --- |
| 后台内存热缓存 | 512 Ki UTF-16 代码单元 | **16 Mi UTF-16 代码单元（32 倍）** |
| 缓存可用性 | 恢复时一次性向 OutputWindow 写入 | 有序 FIFO，**16 Ki/帧**，ACK 后递进 |
| OutputWindow 积压 | 2 Mi 代码单元硬上限，批量回放可能溢出 | 追赶队列以约 **128 Ki** 为高水位；维持现有硬上限 |
| 新的串口打印 | 追赶期间可能被新数据越过 | 追赶期间新数据追加同一 FIFO，按序交付 |
| 隐藏/显示反复切换 | 缺少在途回放状态管理 | 恢复、再次隐藏均保留未回放部分 |
| 大数据输出 | 只保留近期显示缓存 | 超出 16 Mi 丢弃最旧显示内容，磁盘日志继续独立保存 |
| xterm 回滚 | 20 万行 | **保持 20 万行**，避免已有实测确认的 36 万行垃圾回收退化 |
| 用户配置 | 无新增配置 | 保持无新增配置 |

以 8N1 格式、ASCII 满速传输计算，16 Mi 代码单元的理论缓存窗口约为：115200 波特率 24 分钟，921600 波特率 3 分钟。实际日志输出率低于满速时可以保留更久。日志长期留存取决于磁盘空间和日志设置。

## 必须通过的自动化验证

1. 默认容量恰为 16 Mi；超过容量有界淘汰，不截断 UTF-16 代理对。
2. 6 Mi 串口文本后台输出恢复后全部顺序一致；回放过程不触发 2 Mi 显示溢出。
3. 回放期间收到新数据，必须排在原缓存尾部，不能抢在缓存前面。
4. 回放尚未结束时再次隐藏和恢复，不重复、不漏发、不打乱次序。
5. 磁盘内容在显示被限流或丢弃旧显示缓存时继续保留。
6. Windows CI：类型检查、所有单测、构建、打包与原生模块运行测试均通过。

## 实机验收（Windows + USB 串口）

需要外接真实 CH340/CP210x/FTDI 设备或串口回环，记录时间戳与序号，分别在 115200 和 921600 波特率执行：
- 锁屏、关闭屏幕、切换标签与最小化后恢复，覆盖 5 分钟、1 小时与整夜场景。
- 验证磁盘序号完整性、唤醒恢复时间、终端交互延迟、CPU 使用率、进程内存峰值与长期趋势。
- 模拟设备断开 / USB 重新枚举及用户手动休眠，明确不可恢复的采集缺口。
- 在同一台电脑上用相同日志流对比最新 MobaXterm；**未经实机基准测试不得宣称恢复速度绝对领先**。

## 后续增强（P1，本次不冒充已经完成）

1. 原始字节流落盘及可恢复的 ANSI / VT 状态检查点。
2. 按时间和行号索引磁盘日志，提供超过百万行的虚拟历史滚动，无需全量加载到 xterm。
3. 记录恢复耗时与丢显示缓存计数，用真实压测数据优化热缓存大小和重绘策略。
