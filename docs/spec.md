## 1. 项目概述

### 1.1 背景

嵌入式软件日常开发中需要反复使用一堆零散的小工具：计算器、TFTP 服务器、串口助手、hex 查看器……它们来自不同厂商、界面风格不一、有的还要收费或带广告。此外，大量重复性的界面操作（如烧录流程中的连续点击、重复填写对话框）纯靠手工，效率低且易出错。

本项目旨在做一个**单程序、多面板**的开发工具箱，把常用工具集成到一个程序里，并提供**键鼠动作录制与回放**能力，把重复操作自动化。

### 1.2 目标用户

- 嵌入式软件/固件工程师（主要用户）
- 硬件调试、测试人员（次要用户）

### 1.3 设计原则

1. **免安装、绿色便携**：拷贝即用，不写注册表（配置走本地文件）；以 Electron portable 方式分发（体积较大，已接受）。
2. **插件式面板**：每个小工具是一个独立面板，可独立打开、可多个实例（如同时开两个串口）。
3. **常用功能优先**：先做高频工具，低频工具后补。
4. **本地化**：全部功能离线可用，不上传任何数据。

## 2. 总体功能架构

```
DevKit 主程序
├── 主面板（工具箱 Home）

├── 核心工具（P0，已交付）
│    ├── ① 程序员计算器（calc）
│    ├── ② TFTP 服务器（tftp）
│    ├── ③ 键鼠录制回放（macro，含终端快捷命令宏）
│    └── ④ 串口调试助手（serial）★ 界面对齐 MobaXterm
├── 终端类工具（P1，已交付）
│    ├── ⑤ SSH 终端（ssh，xterm + ssh2）
│    └── ⑥ 网络调试助手（net：TCP Server/Client、UDP）
├── 扩展工具（P2，已交付）
│    ├── ⑦ 时间戳转换（timestamp）
│    ├── ⑧ 编码转换（encoding：UTF-8/GBK/UTF-16/Base64/URL）
│    ├── ⑨ 大小端转换（endian）
│    ├── ⑩ 文本对比（diff：文件/文件夹/十六进制，多编码）
│    └── ⑪ 取色器（color：截屏取色/坐标拾取）

│    └── ⑫ 串口TCP桥接（bridge：8 通道串口⇄TCP 透传 + 远程管理）

     └── 键鼠输入测试（input，devOnly）
```

## 3. 核心工具详细需求

### 3.1 程序员计算器（P0）

**用途**：嵌入式开发高频操作——寄存器位运算、进制转换、掩码计算。

| 编号 | 需求 | 说明 |
|---|---|---|
| PC-01 | 多进制同步显示 | 输入一个数，HEX/DEC/OCT/BIN 四进制实时同步显示，BIN 按位分组（4位一组）显示 |
| PC-02 | 位宽切换 | 支持 8/16/32/64 位切换，越界自动截断并有提示 |
| PC-03 | 有符号/无符号 | 有符号数（补码）与无符号表示切换显示 |
| PC-04 | 基础运算 | + - * / %、括号、优先级 |
| PC-05 | 位运算 | AND OR NOT XOR 左移 右移（算术/逻辑） |
| PC-06 | 位编辑器 | 64 个可点击的 bit 格子，点选某位置 1/清 0，实时联动数值显示（**特色功能，寄存器配置神器**） |
| PC-07 | 历史记录 | 计算历史列表，可点击回填 |
| PC-08 | 快捷键 | 完整键盘输入支持，回车出结果 |
| PC-09 | 字节查看 | 以 1~8 字节形式展示内存布局（大端/小端对照） |

### 3.2 TFTP 服务器（P0）

**用途**：嵌入式设备（U-Boot、Bootloader）通过网络下载固件/上传日志的事实标准。

| 编号 | 需求 | 说明 |
|---|---|---|
| TF-01 | 标准协议 | 实现 RFC 1350（TFTP v1.0），支持 RRQ（读/下载到设备）、WRQ（写/从设备上传） |
| TF-02 | 传输模式 | octet（二进制）必须支持；netascii 可选支持 |
| TF-03 | 根目录设置 | 可选择服务目录，支持"打开目录"按钮，拖拽文件进来即可作为下载源 |
| TF-04 | 监听配置 | 绑定网卡/IP（下拉列出本机 IPv4，默认 0.0.0.0 全部网卡；记忆的 IP 失效自动回落）与端口（默认 69），可多实例（不同目录/端口）；标签页随 IP:端口命名便于区分实例 |
| TF-05 | 选项扩展 | 支持 RFC 2347/2348/2349（option 扩展：blksize、timeout、tsize）——大文件传输提速必备 |
| TF-06 | 传输日志 | 实时日志列表：时间、客户端 IP、操作(R/W)、文件名、进度、结果 |
| TF-07 | 并发传输 | 支持多客户端同时传输（每会话独立端口） |
| TF-08 | 防火墙提示 | 启动时检测端口是否可能被拦截，给出 Windows 防火墙放行指引 |
| TF-09 | 最小化运行 | 可最小化到托盘，有传输时托盘图标提示 |

### 3.3 键鼠录制回放（P0，核心特色功能）

**用途**：把"打开烧录工具→点菜单→填对话框→确认"这类重复流程录制成宏，一键重放。

#### 3.3.1 录制

| 编号 | 需求 | 说明 |
|---|---|---|
| MR-01 | 全局钩子录制 | 录制全局（跨窗口）的键盘按下/释放、鼠标移动/按下/释放/滚轮事件 |
| MR-02 | 时间戳 | 每个事件记录相对上一事件的间隔，回放时还原原始节奏 |
| MR-03 | 录制热键 | 全局热键开始/停止录制（默认 `F9`），无需切回本程序 |
| MR-04 | 录制反馈 | 录制中托盘/悬浮窗显示状态和事件计数 |
| MR-05 | 过滤选项 | 可选：忽略鼠标移动（只录点击）、忽略修饰键单独按下、最小间隔阈值过滤抖动 |
| MR-06 | 即时编辑 | 录制完成进入事件列表编辑器 |
| MR-07 | 热键自定义与冲突处理 | 设置界面可修改所有全局热键（录制/回放/急停），冲突时检测提示；提供"录制期间忽略本程序自身热键"开关 |

#### 3.3.2 编辑（事件列表）

| 编号 | 需求 | 说明 |
|---|---|---|
| ME-01 | 事件列表 | 表格展示：序号、类型、键/按钮、位置坐标、延时(ms) |
| ME-02 | 增删改 | 可删除事件、修改延时、修改坐标/按键 |
| ME-03 | 插入特殊步骤 | 手动插入：延时块、文本输入（整段打字）、**等待颜色**（见 ME-04）、循环标记 |
| ME-04 | 等待颜色（重要） | 在坐标 (x,y) 处等待某颜色出现/消失再继续——解决"回放比设备响应快"的经典问题，比死等延时可靠得多 |
| ME-05 | 截图取坐标 | 提供屏幕截图取色/取坐标小工具，方便手动编辑坐标 |
| ME-06 | 分段 | 一个宏可分多个步骤段，段可单独启用/禁用（调试宏时逐段试跑） |

#### 3.3.3 回放

| 编号 | 需求 | 说明 |
|---|---|---|
| MP-01 | 全局热键回放 | 默认 `F10` 开始/停止回放；`F11` 紧急停止（任何时刻可打断） |
| MP-02 | 倍速 | 0.1x~10x 倍速回放，或统一延时压缩 |
| MP-03 | 循环次数 | 单次 / N 次 / 无限循环（无限循环时热键可停） |
| MP-04 | 回放方式 | 优先使用系统级事件注入（SendInput），坐标支持绝对/相对屏幕 |
| MP-05 | 安全机制 | 紧急停止热键优先级最高；回放中 Esc 强制停止（可配置） |
| MP-06 | 后台执行 | 状态悬浮条显示"回放中 x/y"，不影响被操作窗口 |

#### 3.3.4 管理

| 编号 | 需求 | 说明 |
|---|---|---|
| MM-01 | 宏库 | 宏以本地文件保存（JSON 格式，可手改、可进 git），宏库面板列出所有宏 |
| MM-02 | 一键执行 | 宏库中双击或点按钮直接执行；可为每个宏绑定独立热键（如 `Ctrl+Alt+1`） |
| MM-03 | 导入导出 | 单个宏导出/导入，方便在团队/社区间分享 |
| MM-04 | 使用说明 | 内置说明：哪些场景不适用（全屏独占游戏、管理员权限窗口、UAC 弹窗），提示"以管理员身份运行可覆盖大部分场景" |

#### 3.3.5 关键技术点（开发时细化）

- 总体架构：Electron 主进程（Node）跑业务逻辑；**Node 无法直接调用 Win32 低级钩子/SendInput，需自研一个轻量 N-API 原生插件**（C++，几百行，预编译产物随仓库分发）
- 事件捕获：`SetWindowsHookEx(WH_KEYBOARD_LL / WH_MOUSE_LL)`，封装进上述原生插件（备选现成库：uiohook-napi）
- 事件注入：`SendInput`（比 mouse_event/按键消息更可靠），与钩子同一插件实现
- 全局热键：Electron 内置 `globalShortcut`（零原生代码）；若注册失败（被占用）降级为原生插件捕获方案
- 等待颜色/截图取坐标：`desktopCapturer` + `nativeImage.getPixelColor`，纯 JS 实现
- 权限问题：目标窗口若以管理员运行，本程序也需管理员权限（UIPI 限制），文档中明确说明
- 原生插件与 Electron ABI 必须匹配：锁定 Electron 版本，升级时需用匹配的工具链重编译

## 4. 终端类与扩展工具需求

### 4.1 串口调试助手（已交付，M4）

- 枚举串口（含 CH340 驱动毛刺自动复位重试），波特率 1200~12M，数据位/停止位/校验位/RTS-CTS 可配
- ASCII/HEX 收发切换、发送历史下拉、定时循环发送、本地回显开关
- **收发编码可选（UTF-8 / GBK，默认 UTF-8，重启记忆）**：串口线上无编码约定，多数嵌入式设备输出 GBK。收：主进程按所选编码流式解码（iconv-lite，跨批多字节序列不拆坏）；发：ASCII 文本按所选编码编码后下发；切换对打开中的会话即时生效（仅影响之后的线上字节，不回溯已显示内容）。磁盘历史日志与终端内部统一使用解码后的 UTF-8 文本，不受影响
- DTR/RTS 控制、CTS/DSR/DCD 信号轮询显示
- **终端视图**（xterm.js WebGL 渲染）：会话式管理（保存/一键载入）、深色主题、字体字号可调、回滚保持原有固定 20 万行，完整清洗日志从磁盘查询（不是终端画面回放）、终端字体带 CJK 回退（Consolas 等无中文字形时中文不空白）、Ctrl+F 查找（工具栏「查找」按钮等效）、查找打开时终端内选区/复制粘贴不受命中高亮干扰、查找以当前视口为起点（无选区时不跳缓冲区端点）、WebGL 上下文丢失自动重建（防蒙版残影）、复制粘贴（选中点击复制 / 右键粘贴）；**流畅度保障**：输出批量合并窗口 32ms（≈30fps 打印刷新，解析与视口重绘调用次数较 16ms 减半，串口/SSH/本地终端一致）、容器 resize 的 fit 重排节流 120ms（fit 改列数触发全回滚缓冲换行重排，O(行数×列数)，拖侧栏/缩窗不节流会连续叠加 reflow 卡死）
- **本地时间戳显示**（可选开关）：每行前插灰色 `[HH:MM:SS.mmm]`，仅插在行首不打进行中间
- **串口终端零配置默认行为**：固定按真实 VT 语义处理 `\\r`（原地重绘），不擅自改写换行。串口默认静默保护回滚：中和 CSI 3J / ESC c，备用屏切换保持原样；诊断仅留磁盘日志，不弹出技术提示。SSH / 本地终端维持原有标准 VT 行为。移除「裸 CR 换行」「保护回滚」两个用户开关，已有旧配置读入时清理对应字段。
- **持续采集与显示恢复**：串口连接期间自动申请阻止系统空闲休眠（屏幕仍可关闭），切换工具页/最小化/锁屏时主进程继续收串口并落盘。隐藏终端暂停 OutputWindow 向 xterm 派发新的显示帧（原先已发送的有限在途帧仍依次 ACK）、解除仅因显示积压触发的 RTS/CTS 读取暂停，磁盘写入压力保护独立保留，默认保留最多 16 Mi UTF-16 代码单元（约 32 MiB 字符载荷，不含 JS 对象开销），是原 512 Ki 的 32 倍；恢复时每批最多 16 Ki、累计待处理量控制在约 128 Ki，通过 xterm 解析 ACK 逐步补齐并与新到数据按序接续，不向 2 Mi 的 OutputWindow 一次性灌入所有缓存；超过 16 Mi 时只截断较旧的屏幕显示缓存，优先对齐到后续完整日志行并重同步 ANSI 显示状态，提示查询完整磁盘历史，磁盘日志不截断。不新增用户设置项。用户主动让 Windows 真正进入睡眠时，进程可能冻结，无法保证采集。
- **系统休眠/唤醒处理**：主进程监听 suspend/resume，在日志标注真实休眠时长；不再自动清理可能仍有效的 RX 字节，也不主动切换 DTR/RTS。真正睡眠期间已在硬件层丢失的字节无法通过软件补回。
- **磁盘会话历史**：逐行 `[YYYY-MM-DD HH:MM:SS.mmm]` + 清洗后正文，保留 UTF-8 文本；不再在主进程额外保存全量 Buffer。
  - 开启「保留日志」时写入配置日志目录；关闭时仍使用临时磁盘文件支持当前面板查询与导出，关闭面板/重连/正常退出后删除临时文件（非正常退出可能残留）。持久日志不自动删除，用户自行管理磁盘空间。
  - 增量剥 ANSI/VT100，跨批保留解析状态；无换行内容也持续落盘，CR/CRLF 归一为 CRLF，不累积无限长行。输入/发送记录与接收正文按时间顺序写入。
  - **发送（TX）审计**：一次发送 = 一行日志，控制符转可见字面量（`\r`→`<CR>`、`\n`→`<LF>`、`\t`→`<TAB>`、其余 C0→`<XX>`），不经换行归一拆行（否则一个 `\r` 会被归一成换行再拆成两行空日志）。单字符按键仍一行一条（既有语义）
  - 单会话待写队列上限 4 MiB；磁盘失败或积压超限时明确报错并关闭会话，已成功写入的历史仍可查询导出，不宣称错误之后的内容完整。
  - 断开保留文件引用以便导出；销毁面板释放日志引用与输出队列。连接、断开和重复销毁按面板串行执行；正常退出等待服务清理和日志落盘。
  - 「存日志」以 64 KiB 缓冲复制磁盘快照；不全量拼接，不将正文传入渲染进程。「清屏」只清终端，不删除历史日志。
  - 「历史日志」支持当前会话、打开已有 UTF-8 日志、关键词查询和前后分页。每次扫描最多 1 MiB，最多显示 200 条/约 256 KiB；超长行按最多 16 KiB 片段显示与匹配。
  - 日志目录重启记忆，修改后对新会话生效，当前会话保持原文件以保证历史连续。
- **输出流控**：串口/SSH/本地终端统一走原有 `tool:invoke`/事件通道，以会话代号及序号标识输出；只有 xterm 解析完成才回 ACK，旧会话 ACK 无效。每帧最多约 16K UTF-16 单元，128K 高水位、32K 低水位，含在途数据的显示队列硬限 2M 单元（约 4 MiB 字符载荷，不含对象开销）。SSH/PTY 和开启 RTS/CTS 的串口向上游暂停/恢复；无硬件流控的串口持续采集落盘，显示超限明确暂停，清屏恢复，不静默丢弃中间控制流后继续显示。终端侧整批被回滚保护拦下时立即回 ACK（无可解析内容），不让上游流控悬空
- **文件传输**：YMODEM / ZMODEM 收发（进度窗、取消、自动去重命名）
- **快捷命令宏**：与键鼠宏共用宏库，录制终端按键/命令序列并回放（见 4.6）
- 界面习惯对齐 MobaXterm：会话栏宽度可拖动、标签页随所选 COM 口即时命名

### 4.2 SSH 终端（已交付，M4）

- xterm 终端 + ssh2：密码 / 私钥认证，主机/端口/用户名可配
- 远端 pty 联动（resize 转发 setWindow，vim/top 正确布局）
- 会话库（保存/载入，密码明文保存在本机 config.json 并在界面提示风险）
- 磁盘历史、分页查询、流式导出和背压与串口一致，默认持久日志目录为 `ssh-logs/`。
- 本地时间戳显示、终端快捷命令宏与串口共用

本地终端同样使用上述回滚设置、磁盘历史与 ACK 背压；输出默认保留至 `local-terminal-logs/`，可从「历史日志」查询和导出。

### 4.3 网络调试助手（已交付，M4）

- TCP Server / TCP Client / UDP，多连接管理
- ASCII/HEX 收发、定时发送、收发日志

### 4.4 时间戳转换（已交付，M5）

- Unix 时间戳 ↔ 日期互转，s/ms/µs/ns/HEX 自动识别

### 4.5 其他扩展工具（已交付，M5）

- **编码转换**：UTF-8 / GBK（iconv-lite）/ UTF-16 / Base64 / URL 互转
- **大小端转换**：字节序列 LE/BE 多宽度解释与字节交换
- **文本对比**：文件 / 文件夹 / 十六进制对比，多编码，>8000 行截断提示
- **取色器**：截屏取色 / 坐标拾取

### 4.6 终端快捷命令宏（已交付，串口/SSH 共用）

- 与键鼠宏同一份宏库与录制状态；在串口/SSH 终端内录制按键与发送框整条命令为步骤
- 步骤类型：文本命令（ASCII/HEX，可带换行）、按键原样下发
- 多步骤命令列表，可回放、可编辑（共享 `src/shared/term-macro.ts`）
- 列表拖动排序：单条/多条（Ctrl 多选）拖到目标行上半部=插其前、下半部=插其后，组别跟随锚点；插入点判定为纯函数 `resolveDropInsertion`（含单测）
- 支持 MobaXterm 宏文件导入

### 4.7 串口TCP桥接（已交付，M6）

**用途**：把最多 8 路本机串口各自桥接到独立 TCP 监听端口双向透传，让 telnet/netcat 等网络工具直接操作串口设备；远程管理协议跨机器启停通道。

| 编号 | 需求 | 说明 |
|---|---|---|
| BR-01 | 8 路通道 | 每路独立串口/波特率/TCP 监听端口（默认 10001~10008）；串口格式（数据位/校验/停止位/流控）8 路共享，任一路运行时锁定 |
| BR-02 | 双向透传 | 串口读 → 广播所有 TCP 客户端；TCP 客户端 → 写串口；单/多客户端模式（单客户端时新连接踢旧连接） |
| BR-03 | Telnet IAC 解析 | TCP→串口方向剥离 RFC854 协商字节、FF FF 反转义、IAC BREAK → 真实串口 break（可关） |
| BR-04 | 冲突防护 | TCP 端口重复 / 串口被占拒绝启动；「全部启动」冲突静默跳过 |
| BR-05 | 远程管理（服务端模式） | 可选管理端口（默认 9999），远程客户端连入后可查看状态/改配置/启停通道/发 break/列串口；状态变化 100ms 合并广播 |
| BR-06 | 远程管理（客户端模式） | 连远端管理端口远程操作；断线不自动重连，用户手动重连 |
| BR-07 | 管理协议 | 行分隔 JSON 命令：get_channels/update_config/start_channel/stop_channel/start_all/stop_all/get_ports/send_break；服务端状态变化合并广播，新客户端连入即推全量状态 |
| BR-08 | 多身份配置 | 身份按 mode/host/port 派生（`server_<端口>` / `<host>_<端口>`），每身份一份配置，下拉切换/删除，记忆上次身份 |
| BR-09 | 日志 | 界面事件日志上限 1500 行；磁盘日志按身份+按天分文件（`bridge-logs/<身份>_bridge_YYYYMMDD.log`），每条带时间戳 |
| BR-10 | 字节计数 | 每路独立 RX/TX 字节计数 |

### 4.8 未实现（按需再排期）

- HEX/BIN 文件查看与编辑器（S-Record 互转、CRC/MD5/SHA1 摘要）
- DHCP 服务器

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| 性能 | 启动 < 3s；待机内存 < 300MB（Electron 基线，原 150MB 目标按实际栈调整）；串口高速收发不丢包不卡界面 |
| 可靠性 | TFTP 传输校验失败自动重传；宏回放必须可随时强停；系统休眠唤醒后日志标注休眠时长，尽量保留所有已接收字节；连接期间防止系统自动空闲睡眠 |
| 配置 | 所有配置存本地 `config/` 目录（JSON），程序可绿色拷贝迁移 |
| 日志 | 串口/SSH 会话自动日志写用户日志目录（`serial-logs/`/`ssh-logs/` 或用户设置目录），逐行带 `YYYY-MM-DD HH:MM:SS.mmm` 时间戳可追溯；清洗后内容（剥 ANSI、归一换行）与终端显示一致；宏文件即数据，人类可读 |
| 内存 | 不保留全量内存日志；固定 20 万行 xterm 回滚；串口后台热缓存最多 16 Mi 字符代码单元，磁盘写入与实时显示队列仍有独立硬上限，过量显示数据的完整文本继续写盘 |
| 终端回滚 | 默认 20 万行（不为追求数字超过 MobaXterm 而盲目上调）：按真实日志长度（60~100 字符/行）实测，36 万行满缓冲堆 ~138MB、Major GC 暂停 48-54ms，20 万行 ~80MB / 17-27ms；长会话持续打印下 50ms 级暂停即肉眼可见的周期性卡顿。完整历史由磁盘会话历史兜底；**回滚内容不被设备序列销毁**（串口面板默认中和 ED3/RIS，并在重开时退出遗留备用屏，见 4.1） |
| 安全 | 不联网、不上报；录制的宏文件含键盘内容，文档提示勿录制密码输入 |
| 界面 | 中文界面；深色主题优先（嵌入式工程师偏好 + 长时间使用） |
| 分发 | Electron portable 单文件或免安装目录；无代码签名，首次运行会有 SmartScreen 提示，附说明文档 |

## 6. 技术选型（已确认：Electron）

| 项 | 选择 | 说明 |
|---|---|---|
| 应用框架 | Electron（LTS，锁定版本） | UI 灵活、生态成熟；仅支持 Windows |
| 前端框架 | Vue 3 + TypeScript + Vite | 生态成熟、类型安全 |
| UI 组件库 | Element Plus（暗色主题） | 表格/表单组件齐全，中文资料多 |
| 键鼠钩子/注入 | **自研轻量 N-API 原生插件**（SetWindowsHookEx + SendInput） | 灵魂功能可控性优先；备选现成库 uiohook-napi / @nut-tree/nut-js |
| 全局热键 | Electron `globalShortcut` | 内置能力，零原生代码 |
| 截图/取色 | `desktopCapturer` + `nativeImage.getPixelColor` | 内置能力，零原生代码 |
| TFTP 服务器 | Node `dgram` 自实现（RFC 1350 + 2347/2348/2349） | 纯 JS，无外部依赖 |
| 串口 | serialport（N-API prebuild） | 与 Electron 兼容良好 |
| 打包 | electron-builder（portable + 目录两种产物） | 免安装；无签名证书，接受 SmartScreen 提示 |

早期备选方案（Python+PySide6、C#/WPF、C++/Qt）已废弃，最终选定 Electron。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 宏回放在管理员权限的窗口失效 | 文档说明 + 检测到注入失败时提示"以管理员身份运行" |
| 杀毒软件误报键鼠钩子/SendInput | 无代码签名：可提前与 IT 沟通加白；自研插件保持代码极简、来源透明；分发时附说明文档 |
| Electron 体积/内存偏大 | 已接受该代价；portable 分发，不做常驻后台进程 |
| 原生插件与 Electron ABI 不匹配 | 锁定 Electron 版本；预编译产物（prebuild）随仓库分发，升级 Electron 时强制重编译验证 |
| TFTP 穿越防火墙/NAT 问题 | 仅限局域网使用场景，文档说明；随机会话端口需放行 |
| 高波特率串口丢包 | 独立读线程 + 缓冲队列，UI 批量刷新 |
| 范围蔓延（工具越加越多） | 严格按 P0/P1/P2 分期，面板插件化让新增工具成本低但不阻塞发版 |

## 9. 设计决策记录

1. 技术方案：**Electron**（详细栈见第 6 节）
2. 平台：仅支持 Windows
3. 宏热键自定义设置界面：**需要**（已并入 MR-07）
4. 代码签名证书：暂无 → 接受 SmartScreen/杀软提示，缓解措施见第 8 节
5. 串口助手界面习惯：对齐 **MobaXterm**（会话式管理 + 终端视图，见 4.1）
6. SSH 终端加入 M4 交付（原 P1 扩展未单列）：嵌入式调试高频，与串口助手共享 TerminalView 组件与日志管线
7. 终端完整历史以磁盘为源，增量清洗、串行写入、分页查询及有界快照导出；渲染端保留固定的有限回滚，数据解析 ACK 驱动上游背压。
8. HEX/BIN 查看器与 CRC 计算器暂缓（原 4.3/4.4）：优先交付 SSH/diff/取色器等更高频工具，见 4.7
9. 文件传输协议选型：串口内置 YMODEM/ZMODEM（纯 TS 实现进 `tests/` 单测），不引第三方依赖
10. **文档维护规约**：每次新增或修改功能需求/非功能需求时，必须同步更新本 spec（版本号递增、日期更新）；AI 协作流程见仓库根 `AGENTS.md`
