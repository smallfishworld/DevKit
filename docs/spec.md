---

## 1. 项目概述

### 1.1 背景

嵌入式软件日常开发中需要反复使用一堆零散的小工具：计算器、TFTP 服务器、串口助手、hex 查看器……它们来自不同厂商、界面风格不一、有的还要收费或带广告。此外，大量重复性的界面操作（如烧录流程中的连续点击、重复填写对话框）纯靠手工，效率低且易出错。

本项目旨在做一个**单程序、多面板**的开发工具箱，把常用工具集成到一个程序里，并提供**键鼠动作录制与回放**能力，把重复操作自动化。

### 1.2 目标用户

- 嵌入式软件/固件工程师（主要用户）
- 硬件调试、测试人员（次要用户）

### 1.3 设计原则

1. **免安装、绿色便携**：拷贝即用，不写注册表（配置走本地文件）；以 Electron portable 方式分发（体积较大，已接受）。
2. **插件式面板**：每个小工具是一个独立面板，可独立打开、可多个实例（如同时开两个串口）。
3. **常用功能优先**：先做高频工具，低频工具后补。
4. **本地化**：全部功能离线可用，不上传任何数据。

## 2. 总体功能架构

```
DevKit 主程序
├── 主面板（工具箱 Home）
│    ├── 工具网格/图标列表，点击打开对应面板
│    ├── 全局搜索（输入关键字过滤工具）
│    └── 常用工具收藏/置顶（按使用频次自动排序，可选）
├── 核心工具（P0，首版必须）
│    ├── ① 程序员计算器
│    ├── ② TFTP 服务器
│    └── ③ 键鼠录制回放（宏）
├── 扩展工具（P1，次版）
│    ├── 串口调试助手
│    ├── 网络调试助手（TCP Server/Client、UDP）
│    ├── HEX/BIN 文件查看与编辑器
│    └── CRC/校验计算器
└── 扩展工具（P2，按需）
     ├── 时间戳转换
     ├── 进制/编码转换（UTF-8/GBK/Unicode/Base64）
     ├── 数据大小端转换、字节序查看
     ├── DHCP 服务器（嵌入式网络调试用）
     ├── 文本对比（Diff）
     └── 取色器
```

## 3. 核心工具详细需求

### 3.1 程序员计算器（P0）

**用途**：嵌入式开发高频操作——寄存器位运算、进制转换、掩码计算。

| 编号 | 需求 | 说明 |
|---|---|---|
| PC-01 | 多进制同步显示 | 输入一个数，HEX/DEC/OCT/BIN 四进制实时同步显示，BIN 按位分组（4位一组）显示 |
| PC-02 | 位宽切换 | 支持 8/16/32/64 位切换，越界自动截断并有提示 |
| PC-03 | 有符号/无符号 | 有符号数（补码）与无符号表示切换显示 |
| PC-04 | 基础运算 | + - * / %、括号、优先级 |
| PC-05 | 位运算 | AND OR NOT XOR 左移 右移（算术/逻辑） |
| PC-06 | 位编辑器 | 64 个可点击的 bit 格子，点选某位置 1/清 0，实时联动数值显示（**特色功能，寄存器配置神器**） |
| PC-07 | 历史记录 | 计算历史列表，可点击回填 |
| PC-08 | 快捷键 | 完整键盘输入支持，回车出结果 |
| PC-09 | 字节查看 | 以 1~8 字节形式展示内存布局（大端/小端对照） |

### 3.2 TFTP 服务器（P0）

**用途**：嵌入式设备（U-Boot、Bootloader）通过网络下载固件/上传日志的事实标准。

| 编号 | 需求 | 说明 |
|---|---|---|
| TF-01 | 标准协议 | 实现 RFC 1350（TFTP v1.0），支持 RRQ（读/下载到设备）、WRQ（写/从设备上传） |
| TF-02 | 传输模式 | octet（二进制）必须支持；netascii 可选支持 |
| TF-03 | 根目录设置 | 可选择服务目录，支持"打开目录"按钮，拖拽文件进来即可作为下载源 |
| TF-04 | 监听配置 | 绑定网卡/IP 与端口（默认 69），可多实例（不同目录/端口） |
| TF-05 | 选项扩展 | 支持 RFC 2347/2348/2349（option 扩展：blksize、timeout、tsize）——大文件传输提速必备 |
| TF-06 | 传输日志 | 实时日志列表：时间、客户端 IP、操作(R/W)、文件名、进度、结果 |
| TF-07 | 并发传输 | 支持多客户端同时传输（每会话独立端口） |
| TF-08 | 防火墙提示 | 启动时检测端口是否可能被拦截，给出 Windows 防火墙放行指引 |
| TF-09 | 最小化运行 | 可最小化到托盘，有传输时托盘图标提示 |

### 3.3 键鼠录制回放（P0，核心特色功能）

**用途**：把"打开烧录工具→点菜单→填对话框→确认"这类重复流程录制成宏，一键重放。

#### 3.3.1 录制

| 编号 | 需求 | 说明 |
|---|---|---|
| MR-01 | 全局钩子录制 | 录制全局（跨窗口）的键盘按下/释放、鼠标移动/按下/释放/滚轮事件 |
| MR-02 | 时间戳 | 每个事件记录相对上一事件的间隔，回放时还原原始节奏 |
| MR-03 | 录制热键 | 全局热键开始/停止录制（默认 `F9`），无需切回本程序 |
| MR-04 | 录制反馈 | 录制中托盘/悬浮窗显示状态和事件计数 |
| MR-05 | 过滤选项 | 可选：忽略鼠标移动（只录点击）、忽略修饰键单独按下、最小间隔阈值过滤抖动 |
| MR-06 | 即时编辑 | 录制完成进入事件列表编辑器 |
| MR-07 | 热键自定义与冲突处理 | 设置界面可修改所有全局热键（录制/回放/急停），冲突时检测提示；提供"录制期间忽略本程序自身热键"开关 |

#### 3.3.2 编辑（事件列表）

| 编号 | 需求 | 说明 |
|---|---|---|
| ME-01 | 事件列表 | 表格展示：序号、类型、键/按钮、位置坐标、延时(ms) |
| ME-02 | 增删改 | 可删除事件、修改延时、修改坐标/按键 |
| ME-03 | 插入特殊步骤 | 手动插入：延时块、文本输入（整段打字）、**等待颜色**（见 ME-04）、循环标记 |
| ME-04 | 等待颜色（重要） | 在坐标 (x,y) 处等待某颜色出现/消失再继续——解决"回放比设备响应快"的经典问题，比死等延时可靠得多 |
| ME-05 | 截图取坐标 | 提供屏幕截图取色/取坐标小工具，方便手动编辑坐标 |
| ME-06 | 分段 | 一个宏可分多个步骤段，段可单独启用/禁用（调试宏时逐段试跑） |

#### 3.3.3 回放

| 编号 | 需求 | 说明 |
|---|---|---|
| MP-01 | 全局热键回放 | 默认 `F10` 开始/停止回放；`F11` 紧急停止（任何时刻可打断） |
| MP-02 | 倍速 | 0.1x~10x 倍速回放，或统一延时压缩 |
| MP-03 | 循环次数 | 单次 / N 次 / 无限循环（无限循环时热键可停） |
| MP-04 | 回放方式 | 优先使用系统级事件注入（SendInput），坐标支持绝对/相对屏幕 |
| MP-05 | 安全机制 | 紧急停止热键优先级最高；回放中 Esc 强制停止（可配置） |
| MP-06 | 后台执行 | 状态悬浮条显示"回放中 x/y"，不影响被操作窗口 |

#### 3.3.4 管理

| 编号 | 需求 | 说明 |
|---|---|---|
| MM-01 | 宏库 | 宏以本地文件保存（JSON 格式，可手改、可进 git），宏库面板列出所有宏 |
| MM-02 | 一键执行 | 宏库中双击或点按钮直接执行；可为每个宏绑定独立热键（如 `Ctrl+Alt+1`） |
| MM-03 | 导入导出 | 单个宏导出/导入，方便在团队/社区间分享 |
| MM-04 | 使用说明 | 内置说明：哪些场景不适用（全屏独占游戏、管理员权限窗口、UAC 弹窗），提示"以管理员身份运行可覆盖大部分场景" |

#### 3.3.5 关键技术点（开发时细化）

- 总体架构：Electron 主进程（Node）跑业务逻辑；**Node 无法直接调用 Win32 低级钩子/SendInput，需自研一个轻量 N-API 原生插件**（C++，几百行，预编译产物随仓库分发）
- 事件捕获：`SetWindowsHookEx(WH_KEYBOARD_LL / WH_MOUSE_LL)`，封装进上述原生插件（备选现成库：uiohook-napi）
- 事件注入：`SendInput`（比 mouse_event/按键消息更可靠），与钩子同一插件实现
- 全局热键：Electron 内置 `globalShortcut`（零原生代码）；若注册失败（被占用）降级为原生插件捕获方案
- 等待颜色/截图取坐标：`desktopCapturer` + `nativeImage.getPixelColor`，纯 JS 实现
- 权限问题：目标窗口若以管理员运行，本程序也需管理员权限（UIPI 限制），文档中明确说明
- 原生插件与 Electron ABI 必须匹配：锁定 Electron 版本，升级时需用匹配的工具链重编译

## 4. 扩展工具需求（P1，概要）

### 4.1 串口调试助手
- 枚举串口，波特率 1200~12M，数据位/停止位/校验位可配
- ASCII/HEX 收发切换、收发计数、时间戳、日志保存
- 发送区多条自定义命令（可命名、可快捷发送）、循环发送
- DTR/RTS 控制（某些板子进 Bootloader 需要）
- 波特率较高时接收不卡 UI（独立线程 + 环形缓冲）
- 界面习惯对齐 MobaXterm：会话式管理（保存/快速重连）、终端流式视图、深色主题、发送历史下拉

### 4.2 网络调试助手
- TCP Server / TCP Client / UDP，多连接管理
- ASCII/HEX 收发、定时发送、收发日志

### 4.3 HEX/BIN 文件查看器
- 十六进制视图 + ASCII 栏，跳转地址、搜索
- HEX(S-Record) 与 BIN 互转，填充(0xFF)、拼接、截取
- 显示文件 CRC32/MD5/SHA1（核对固件版本用）

### 4.4 CRC/校验计算器
- 常见 CRC 算法：CRC-8/16/MODBUS/CCITT/XMODEM-32 等（参数可配：多项式、初值、异或、位序）
- 对文本或文件计算 SUM/CRC32/MD5/SHA1

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| 性能 | 启动 < 3s；待机内存 < 300MB（Electron 基线，原 150MB 目标按实际栈调整）；串口高速收发不丢包不卡界面 |
| 可靠性 | TFTP 传输校验失败自动重传；宏回放必须可随时强停 |
| 配置 | 所有配置存本地 `config/` 目录（JSON），程序可绿色拷贝迁移 |
| 日志 | 工具运行日志写 `logs/`，异常可追溯；宏文件即数据，人类可读 |
| 安全 | 不联网、不上报；录制的宏文件含键盘内容，文档提示勿录制密码输入 |
| 界面 | 中文界面；深色主题优先（嵌入式工程师偏好 + 长时间使用） |
| 分发 | Electron portable 单文件或免安装目录；无代码签名，首次运行会有 SmartScreen 提示，附说明文档 |

## 6. 技术选型（已确认：Electron）

| 项 | 选择 | 说明 |
|---|---|---|
| 应用框架 | Electron（LTS，锁定版本） | UI 灵活、生态成熟；仅支持 Windows |
| 前端框架 | Vue 3 + TypeScript + Vite | 生态成熟、类型安全 |
| UI 组件库 | Element Plus（暗色主题） | 表格/表单组件齐全，中文资料多 |
| 键鼠钩子/注入 | **自研轻量 N-API 原生插件**（SetWindowsHookEx + SendInput） | 灵魂功能可控性优先；备选现成库 uiohook-napi / @nut-tree/nut-js |
| 全局热键 | Electron `globalShortcut` | 内置能力，零原生代码 |
| 截图/取色 | `desktopCapturer` + `nativeImage.getPixelColor` | 内置能力，零原生代码 |
| TFTP 服务器 | Node `dgram` 自实现（RFC 1350 + 2347/2348/2349） | 纯 JS，无外部依赖 |
| 串口 | serialport（N-API prebuild） | 与 Electron 兼容良好 |
| 打包 | electron-builder（portable + 目录两种产物） | 免安装；无签名证书，接受 SmartScreen 提示 |

早期备选方案（Python+PySide6、C#/WPF、C++/Qt）已废弃，最终选定 Electron。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 宏回放在管理员权限的窗口失效 | 文档说明 + 检测到注入失败时提示"以管理员身份运行" |
| 杀毒软件误报键鼠钩子/SendInput | 无代码签名：可提前与 IT 沟通加白；自研插件保持代码极简、来源透明；分发时附说明文档 |
| Electron 体积/内存偏大 | 已接受该代价；portable 分发，不做常驻后台进程 |
| 原生插件与 Electron ABI 不匹配 | 锁定 Electron 版本；预编译产物（prebuild）随仓库分发，升级 Electron 时强制重编译验证 |
| TFTP 穿越防火墙/NAT 问题 | 仅限局域网使用场景，文档说明；随机会话端口需放行 |
| 高波特率串口丢包 | 独立读线程 + 缓冲队列，UI 批量刷新 |
| 范围蔓延（工具越加越多） | 严格按 P0/P1/P2 分期，面板插件化让新增工具成本低但不阻塞发版 |

## 9. 设计决策记录

1. 技术方案：**Electron**（详细栈见第 6 节）
2. 平台：仅支持 Windows
3. 宏热键自定义设置界面：**需要**（已并入 MR-07）
4. 代码签名证书：暂无 → 接受 SmartScreen/杀软提示，缓解措施见第 8 节
5. 串口助手界面习惯：对齐 **MobaXterm**（会话式管理 + 终端视图，见 4.1）
