# DevKit 串口后台采集与 16 Mi 缓存代码审查（2026-10-28）

## 审查范围

审查前两轮改动：
- `b1f8da7`：串口防系统空闲休眠、后台捕获及两项技术开关删除
- `89614e6`（PR #2）：16 Mi 后台热缓存、16 Ki 分帧与 ACK 追赶

重点覆盖主进程 SerialService、TerminalRuntime、OutputWindow、DisplayBacklog，以及 Vue 串口面板的隐藏/恢复事件。

## 本轮已修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| 高 | 标签隐藏后，旧 OutputWindow 中排队但尚未发送的帧仍可能被 ACK 驱动继续派发到 xterm | 增加 `suspendDelivery()/resumeDelivery()`。停止派发新帧；已经发送的最多约 128 Ki 窗口仍正常 ACK，不改变其交付顺序 |
| 高 | RTS/CTS 会话隐藏时，显示积压压力可持续暂停串口读取，使后台采集目的落空 | 隐藏期间忽略 display 流控压力；独立的 disk 压力仍生效。显示恢复后按待处理量重新同步压力 |
| 中 | 16 Mi 环形热缓存淘汰头部可能从 ANSI/VT 指令或日志行的中间开始，造成不完整终端控制指令 | 淘汰后优先向下一个完整 LF 行界对齐（最多额外查找 4 Ki）；回放时先结束可能未闭合的 OSC/DCS，重置 SGR，并明确提示磁盘历史可追溯。无 LF 设备仍保留有界尾巴 |
| 中 | Unicode 代理对（UTF-16 surrogate pair）恰好跨两个接收块时，回放分帧可能输出半个字符 | 在后台缓存 append 时合并跨块代理对，确保既不截断也不将其拆在相邻显示帧 |
| 低 | 系统唤醒只要 gap>0 即显示警告，干扰正常使用 | 只对真实长休眠（>=30 s）保留非阻塞警告，仍不做自动清空接收缓存或 DTR 复位 |

## 测试与验收

新增覆盖：
- 隐藏期间 ACK 不应驱动后续 OutputWindow 继续派发。
- 带 RTS/CTS 的高水位 display 压力在隐藏时消除、重新显示后恢复；磁盘继续落盘。
- 已有前台帧排队时隐藏、追加 64 Ki 后恢复，显示按原始 FIFO 顺序（含未发送的前台帧）输出，且不触发溢出。
- 热缓存截断优先从完整行开始，跨接收块 UTF-16 代理对仍作为一个字符回放。

保留此前单测：16 Mi 上限、多 MiB ACK 分帧追赶、反复切换及磁盘日志完整性。

## 未宣称已解决的限制

1. Windows 真正进入 S3 睡眠时串口硬件可能丢字节，任何本机后台缓存均无法挽回。
2. 16 Mi 热缓存是**屏幕近期回放缓存**，不是完整原始字节记录：现有磁盘日志仍是剥除 ANSI 的可阅读文本，暂不能按原始 VT 状态逐字节重建颜色/光标。
3. 大量历史回放所需的真实耗时、CPU 峰值和 Windows 不同 USB 转串口驱动的行为，仍需同机实测；不能以 CI 通过替代 MobaXterm 对照性能数据。
4. 已经发往渲染进程的少量在途帧仍由 xterm 异步解析并 ACK；隐藏控制只停止**后续新帧派发**，不会取消已投递的 xterm 写操作。

## 设计不变项

默认后台缓存 16 Mi UTF-16 单元，原始独立 xterm 回滚 20 万行；维持 ACK 帧控、磁盘日志独立采集、不增加用户开关，不主动 flush RX 缓存和不主动修改 DTR/RTS。
